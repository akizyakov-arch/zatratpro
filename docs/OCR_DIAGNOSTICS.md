# Диагностика ожидания OCR.space

Фото обрабатывается в общем `document_processing`: до двух попыток OCR по
120 секунд с паузой 3 секунды. Поэтому `handle_ms` около 243000 и TimeoutError
согласуются с двумя внешними deadline. Это указывает на этап OCR, но не отличает
проблему сети VPS от задержки провайдера. К разбору DeepSeek код переходит после
успешного получения OCR-текста. PDF имеет отдельный общий лимит 600 секунд;
общий сценарий загрузки — 750 секунд. Качество конвертации PDF не изменено.

Логирование:

- `document_ocr_start/done/failed`: провайдер, номер попытки, время, тип ошибки;
- `ocr_space_start/response/read_timeout/failed/cancelled`: случайный код запроса,
  попытка HTTP, статус и время. Cancelled может быть внешним deadline или остановкой
  процесса и само по себе не доказывает сбой сервиса;
- `document_parse_start/done/failed`: отдельный этап структурирования DeepSeek.

Успешное HTTP 200 ещё не доказывает распознавание: возможна ошибка в JSON провайдера.
Тело ответа, ключ, имя файла, изображение и OCR-текст новыми сообщениями не логируются.
HTTP-ошибка возвращает безопасный код проверки вместо исходной сетевой строки.
Режим повтора и существующие лимиты ожидания сохранены. После двух deadline для
фото возвращается понятная `OCRSpaceError`, которую показывают оба бота.

Для VPS:

```bash
docker logs --since=10m --tail=150 zatratpro-bot 2>&1
docker logs --since=10m --tail=150 fiinops-zatratpro-max-1 2>&1
```

На MAX текущий последовательный poller ждёт завершения OCR; эти изменения
добавляют диагностику, но не вводят очередь фоновых задач и не устраняют
неустановленную внешнюю сетевую/провайдерскую причину таймаута.

## Проверка разделения провайдеров

При `ocr_space` фабрика создаёт `OCRSpaceService`; multipart POST содержит только
`apikey=OCR_SPACE_API_KEY`, `language=rus`, `OCREngine=2` и бинарный JPEG в `file`.
Ключ DeepSeek, поля `messages`/`image_url`, модель и JSON-запрос Vision туда не входят.
Отдельный тест разбирает MIME фактического HTTPX-запроса и проверяет набор полей,
совпадение байтов файла, отсутствие Authorization и ключа другого провайдера.

После успешного OCR его текст передаётся в `DeepSeekService.extract_document`
для выделения полей. Поэтому участие DeepSeek во втором этапе штатно и не является
подменой OCR. Таймаут до `document_ocr_done` происходит раньше этого этапа.
Разделение подтверждено проверками; причина таймаута живого VPS этим не установлена.
