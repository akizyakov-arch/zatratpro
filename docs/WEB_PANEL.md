# Веб-панель FIINOPS

Панель работает с той же PostgreSQL, пользователями и финансовыми сервисами,
что Telegram-бот. Требования: [WEB_PANEL_REQUIREMENTS.md](WEB_PANEL_REQUIREMENTS.md).

Для внешнего запуска подготовлена [конфигурация HTTPS с Caddy](DEPLOYMENT.md),
проверка настроек и скрипт создания проверенной резервной копии.
Панель руководителя также можно открыть как [мини-приложение Telegram](TELEGRAM_MINI_APP.md).

## Доступные сценарии

- Руководитель: обзор, выдачи денег, учёт расходов и подтверждение возвратов, бизнес-карты,
  документы и дубли, проекты, сотрудники, отчёты и полный Excel.
- Владелец системы: компании, назначение руководителей и сотрудников, приглашения,
  приостановка доступа и системная статистика. Финансовые действия компании
  автоматически владельцу не предоставляются.
- Профиль: связанные аккаунты, браузерные сессии, выход с устройства или со всех.
- Сотрудники загружают документы и подтверждают операции через Telegram.

Веб-панель не выполняет банковские переводы. Привязка расхода к бизнес-карте
сразу фиксирует источник оплаты и не является сверкой с банковской выпиской. Загрузка в браузере,
хранение оригиналов, импорт выписок и сторно проведённых операций остаются
следующими этапами. Старые фото не восстанавливаются из распознанного текста.

## Обзор по открытым проектам

В «Обзоре» после общих показателей показаны карточки всех неархивных проектов,
включая проекты без документов и денег. Пока «открытый» означает `status=active`;
отдельные этапы выполнения проекта не вводятся.

Карточка показывает затраты по документам в RUB, получено, расходы, возвраты,
деньги сотрудников, задолженность компании, ожидание получения и бизнес-карты.
Расшифровка раскрывает начальный/конечный остаток и возвраты к подтверждению.
Выбранный период сохраняется при переходе к документам, выдачам и отчёту проекта.

Общие показатели компании включают архивные проекты. В проектных карточках
остатки считаются внутри проекта по каждому сотруднику; в общем показателе
сотрудник сначала суммируется по всем проектам. Поэтому суммы показателей
«У сотрудников»/«Компания должна» по проектам могут отличаться от общих.
Все части серверного обзора читаются из одного снимка БД.

## Первый запуск и обновление

Нужны Python 3.11+, PostgreSQL с исходной схемой `db/init/001_init.sql` и переменные
из `.env.example`. Бот и панель должны использовать одинаковое подключение к БД
и `BOT_OWNER_TELEGRAM_ID`.

Перед первым запуском этой версии сделайте резервную копию БД и остановите старые
процессы бота. Миграции 008–010 добавляют вход, решения по расходам и журнал;
миграция 009 меняет уникальность привязок чеков. Старый код финансовых операций
после неё несовместим с новой схемой. Бот и панель обновляются совместно.
Новые процессы автоматически применяют миграции под общей блокировкой.

```bash
pip install -r requirements.txt
python -m app.web
```

По умолчанию сервер слушает `127.0.0.1:8080`. Отдельно запускается обновлённый бот:

```bash
python -m app.main
```

Для Docker Compose, после резервной копии:

```bash
docker compose stop zatratpro-bot zatratpro-web
docker compose up -d --build zatratpro-bot zatratpro-web
```

Контейнер панели публикует порт только на `127.0.0.1:8080` хоста. Для внешнего
доступа перед ним нужен HTTPS reverse proxy; порт PostgreSQL публиковать не требуется.

## Адрес и параметры

| Переменная | Назначение |
| --- | --- |
| `WEB_ORIGIN` | Внешний HTTPS origin без пути, например `https://fin.example.com` |
| `WEB_ALLOWED_HOSTS` | Допустимые имена хоста через запятую; по умолчанию хост `WEB_ORIGIN` |
| `WEB_COOKIE_SECURE` | `true` для HTTPS; значение по умолчанию `true` |
| `WEB_BOT_USERNAME` | Имя существующего бота без `@`, по умолчанию `prozatrat_bot` |
| `WEB_HOST`, `WEB_PORT` | Адрес прослушивания; по умолчанию `127.0.0.1`, `8080` |
| `WEB_TRUSTED_PROXIES` | Адреса доверенных reverse proxy; по умолчанию `127.0.0.1` |

Для локальной разработки по HTTP явно установите:

```dotenv
WEB_ORIGIN=http://localhost:8080
WEB_ALLOWED_HOSTS=localhost,127.0.0.1
WEB_COOKIE_SECURE=false
```

Локальный HTTP-режим предназначен для разработки. Внешняя панель использует HTTPS
и `WEB_COOKIE_SECURE=true`. Reverse proxy должен сохранять `Host` и передавать
`X-Forwarded-Proto`; доверять следует только адресу своего proxy.

## Как войти

1. Откройте панель и нажмите кнопку входа через Telegram.
2. Перейдите в существующего бота по показанной ссылке и запустите запрос.
3. Проверьте сведения о браузере и подтвердите вход.
4. Вернитесь в тот же браузер: панель автоматически откроет ваш кабинет.

Запрос действует 5 минут и одноразовый. Сессию получает только исходный браузер.
Срок сессии — до 7 дней, бездействие — до 24 часов. Допускаются существующий
руководитель активной компании и действующий владелец системы. Пользователь
без подходящей роли получает объяснение в боте. Вход не создаёт второго сотрудника.

Веб-ключи сессий хранятся в БД в виде хешей. Браузер получает HttpOnly/SameSite
cookie и отдельный CSRF-токен для форм. При приостановке доступа действующие
веб-сессии отзываются; возобновление требует нового подтверждения входа.

## Проверки

Полный набор проверок использует отдельные случайно названные базы:

```bash
RUN_DATABASE_TESTS=1 python -m unittest discover -s tests -v
```

Новые наборы `test_web_auth`, `test_web_finance`, `test_web_workspace`,
`test_web_reports` и `test_web_api` проверяют вход, роли, сквозной сценарий
бот/веб, конкурентные решения, расчёты, фильтры и полный XLSX. Они не вызывают
Telegram/OCR/DeepSeek и не меняют рабочую базу.

Проверка 25.10.2026: полный набор **148 тестов прошёл без ошибок и пропусков**.
Дополнительно прошли `pip check`, компиляция Python, `node --check` для JavaScript
и проверка форматирования Git. В Chromium на отдельной базе проверены 14 экранов,
выдача, автоматический учёт расходов и подтверждение возвратов, Excel, вход с отказом и повтором, сортировка,
денежные сводки и мобильное меню при ширине 390 px. В браузерной проверке решение
о входе передавалось через настоящий сервис авторизации без отправки в Telegram;
проверка с реальным ботом выполняется после совместного развёртывания.

Для ручной проверки: создать выдачу в панели → подтвердить в боте → загрузить
и приложить чек → проверить учёт в панели → сравнить остаток в боте и Excel.
Отдельно проверить отклонение возврата с причиной и повторную заявку на возврат.

До развёртывания нового бота на той же БД подтверждение веб-входа через старый
работающий бот недоступно: старый процесс ещё не знает новый обработчик.

### Дубли, включая архивные проекты

В обзоре руководителя предупреждение «Дубли документов к проверке» показывает
все неразобранные точные и возможные дубли компании за всё время. Период обзора
и архивирование проекта не скрывают предупреждение. Переход открывает общий
список (`duplicate_status=flagged`, `period=all_time`); проект в архиве отмечен
в списке, карточке и сравнении. Счётчики дублей внутри обычных отчётов по-прежнему
относятся к выбранному периоду.

Документ без привязки к выдаче/карте уже входит в затраты. Эта привязка нужна
для расчётов по деньгам. Подозрение на дубль не исключает документ автоматически;
руководитель может сравнить записи и оставить отдельными либо удалить ошибочный
дубль, если у него нет финансовой истории.

Назначение выдачи необязательно. После подтверждения получения сотрудником
оформившему выдачу руководителю приходит уведомление в Telegram со ссылкой
на карточку. В панели получение также видно в карточке и реестре выдач.
