# Проверка задержек MAX

Проверять обычные кнопки отдельно от OCR и голоса: текущий Long Polling
обрабатывает страницу последовательно. Долгий внешний запрос задерживает следующие
события. `timeout=30` — максимальное ожидание пустого Long Polling, а не обязательная
пауза перед каждым ответом. Искусственная пауза 550 мс между `/answers` и
`/messages` удалена после замеров на VPS. Запросы идут последовательно без
дополнительного ожидания. При HTTP 429 poller сохраняет существующий механизм
повтора страницы с ожиданием `Retry-After` (1–60 с) и увеличением интервала при
повторных ошибках.

## Сеть с VPS

После обновления образа выполнить, не останавливая бот:

```bash
docker exec fiinops-zatratpro-max-1 python -m app.max_bot --latency-check
```

Три последовательных GET `/me` измеряют доступ к официальному API с проверкой TLS.
Первый включает холодное соединение; следующие используют соединение повторно.
Проверка не читает `/updates`, не меняет webhook, не обращается к БД,
не посылает сообщения и не запускает второго poller.
Это замер API, а не полного времени от нажатия кнопки до отображения на телефоне.

## Обычное меню

В MAX по очереди нажать «Проекты», «Назад», «Деньги», «Назад»,
дожидаясь ответа после каждой кнопки. Затем:

```bash
docker logs --since=5m --tail=100 fiinops-zatratpro-max-1 2>&1
```

Для каждого завершённого события появляется строка `max_event`:

- `age_ms` — возраст события в начале обработки; включает доставку и очередь,
  зависит от синхронизации часов VPS с MAX, не является точным сетевым временем.
- `ack_ms` — подтверждение callback.
- `handle_ms` — обработка сценария, включая БД и возможные внешние сервисы.
- `send_ms` — отправка ответа, включая разбиение длинного текста.
- `total_ms` — обработка с подтверждением и отправкой; без предыдущего ожидания очереди.
- `pending` — сколько событий осталось в текущей странице, не вся очередь MAX.

Незаполненный timestamp даёт `age_ms=unknown`. Содержимое сообщений, идентификаторы,
коды приглашений, суммы и URL не пишутся. Строка относится к завершённой обработке;
если обработка оборвалась, смотреть соседнюю ошибку. HTTP 403 при отправке может
означать пропущенного недоступного получателя, а не доставленный ответ.

Высокий `/me` указывает на сеть/API; низкий `/me` не исключает задержек `/answers`
или `/messages`. Высокий `handle_ms` требует профилирования сценария/БД. Высокий
`age_ms` при быстром выполнении возможен при накоплении событий или долгом запросе
перед ними. Изменять конкурентность финансовых событий или лимит API следует после
замеров, с сохранением порядка, дедупликации и блокировки poller.
