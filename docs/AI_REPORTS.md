# Голосовые и текстовые финансовые отчёты

Открыть: **Отчёты → ИИ-отчёты: голосом или текстом**. Внутри можно писать
обычные сообщения или отправлять голосовые. `/ask ВОПРОС` работает из любого
раздела. Кнопка выхода и переходы в другое меню завершают текстовый режим.
Текущие действия создания проекта, приглашения и другие формы не перехватываются.
Режим и параметры последнего запроса сохраняются до 15 минут и переживают
перезапуск. При смене компании старый контекст не используется.

## Поддерживаемый каталог

| Тема | Примеры |
|---|---|
| Выдачи | Сколько выдали Иванову по проектам за октябрь? Кто получил больше всего выдач? Когда была последняя выдача? Какие выдачи отменены? Кому выдавали несколько раз за день? |
| Получение | Сколько сотрудники подтвердили к получению? Сколько получил Петров по проекту за период? |
| Расходы | Сколько расходов сотрудника принято? Какие расходы ожидают проверки больше недели? Какие отклонены и почему? Кто отправил расход повторно после отказа? Покажи самые крупные расходы. |
| Возвраты | Сколько вернули? Кто возвращал деньги? Какие возвраты ещё на проверке или отклонены? |
| Остатки | Сколько сейчас у сотрудников? Сколько компания должна Иванову? Остаток на конец сентября по проектам. |
| Карты | Сколько расходов принято по бизнес-картам? Разбей по картам/проектам. Какие операции ещё на проверке? |
| Документы | Сколько загружено документов и на какую сумму? Покажи документы сотрудника. Найди накладную по номеру. Какие документы без привязки к оплате? Есть дубли? |
| Поставщики | Документы какого поставщика на самую большую сумму? У кого закупались чаще? Покажи документы поставщика по проекту. |
| Товары | Какие товары покупали у поставщика? Покажи покупки кабеля и указанные цены за период. |
| Динамика | Сравни расходы сентября и октября. По каким проектам сумма выросла больше всего? Покажи суммы по неделям/месяцам. |
| Общая сводка | Что с деньгами компании? Сводка по сотрудникам/проектам. Какие операции требуют внимания? У кого есть деньги, но нет принятых расходов/возвратов больше недели? |
| Уточнения | А за прошлый месяц? По сотрудникам. Разбей по проектам. Покажи операции. В Excel. |

Дополнительные фильтры: проект, открытые/архивные проекты, сотрудник, поставщик,
карта, наименование товара, номер/тип документа, сумма от/до, срок ожидания,
точные даты. Фильтры применяются только к подходящим типам отчёта; несовместимая
комбинация вызывает уточнение. Неоднозначное имя требует полного названия.
Краткие команды изменения группировки, прошлого месяца и Excel распознаются
локально и не требуют нового обращения к модели.

## Как считаются показатели

- Выдачи — по дате оформления, получение — по дате подтверждения.
- Принятые расходы и возвраты — по дате решения. Ожидающие — по дате подачи;
  отклонённые — по дате отказа. Статусы операционных списков текущие.
- По умолчанию расходы/возвраты/карты включают принятые операции. Можно явно
  запросить ожидающие, отклонённые или все статусы.
- Документы и позиции — по дате загрузки. Это не доказательство оплаты.
- Денежные остатки и сводка используют общие финансовые сервисы с датами
  получения/согласования и состоянием на конец периода. Неподтверждённые выдачи
  в остаток не входят. Деньги карт не увеличивают подотчётный остаток.
- Общая сумма «у сотрудников» сначала сводится по каждому человеку между
  проектами, затем выделяется положительный остаток. Долг компании выделяется
  отдельно. Сумма положительных остатков по отдельным проектам может отличаться.
- Валюты не складываются. Каждая показана отдельно. Периоды UTC, конечная дата
  включительна; понятые границы и фильтры отображаются в ответе.
- Сравнение считает разницу по валютам/показателям, для сгруппированных операций
  показывает вклад групп. Это числовое объяснение изменения, не утверждение
  о реальных причинах закупок.

В чате показывается до 50 строк/групп (обычно 20), итоги считаются по всем
найденным операциям. Excel содержит параметры, ответ и рассчитанные строки
текущего и сравниваемого периода. Детальные списки ограничены 5000 строками
на период; при превышении нужно сузить фильтры. Для группировок итоговые строки
покрывают все найденные группы. Строки Excel защищены от выполнения формул.

## Ограничения данных

Банковские остатки, прибыль, бюджеты, задолженность поставщикам и прогнозы пока
не учитываются. Данные о товарах берутся из распознавания; единицы и варианты
названий не нормализованы, поэтому количества разных строк не складываются
автоматически. Повторные заявки после отказа ищутся по тому же ID документа; заново загруженный
файл не считается автоматически той же заявкой. Отсутствие принятых расходов и
возвратов проверяется по сотруднику за N дней до конца периода. Это признаки
для проверки: они не доказывают мошенничество и не устанавливают нормативную
просрочку отчётности, поскольку сроки отчётности ещё не заведены.

## Подключение и защита

AssemblyAI Universal-2 распознаёт русский (`language_code=ru`). Нужен
`ASSEMBLYAI_API_KEY`; облачный секрет `ASSAMBLY` также принимается. Голос — до
120 секунд/10 МБ, обработка ограничена по времени. Аудио хранится в ограниченном
буфере памяти. После обработки запрашивается удаление транскрипции; срок
хранения загруженного аудио определяется политикой провайдера.

Модель получает вопрос, схему разрешённых параметров и короткий контекст
фильтров. Документы и операции в модель не отправляются; SQL от модели не
принимается. База считает деньги в одном снимке, текст и Excel формируются
кодом. Контекст хранится в `ai_report_sessions` (миграция 015), без голосовых,
вопросов и денежных сумм. Лимит — 5 запросов в минуту на пользователя.

Доступ только у руководителя своей активной компании; сотрудник и системный
владелец не получают этих финансовых прав. Компания/роль проверяются до API,
при построении отчёта и перед отправкой результата/Excel. Содержимое голосовых
и ключи не записываются в журнал.

## Проверка

На рабочей базе с тестовыми данными проверены настоящим DeepSeek вопросы о
документах, разбивка по сотрудникам, Excel, выдачи Иванову, деньги у сотрудников,
ожидающие операции, сравнение сентября и октября и товары поставщика.
Нулевые выдачи тестовых сотрудников ожидаемы: им пока не создавали выдачи.
Подключение AssemblyAI проверено циклом загрузки/обработки аудио без речи;
качество живой русской речи проверяется голосовым в Telegram.

## Список проектов и похожие названия

«Какие проекты сейчас открыты/активны?» обращается к справочнику проектов,
а не к группировке финансовых операций. Показываются и пустые проекты; полный
вопрос сбрасывает фильтры прошлого сотрудника/проекта. По умолчанию в чате до
20 строк с явным общим числом; весь список доступен в Excel. Архивные проекты
можно запросить отдельно. Это текущий статус, а не восстановление состояния
справочника на прошлую дату.

Название ищется внутри компании: точное/однозначное частичное совпадение,
игнорирование регистра, пробелов и пунктуации, транслитерация кириллицы/латиницы.
Для опечаток и похожего звучания предлагаются до 8 ближайших вариантов. Даже
при одном похожем варианте финансовый фильтр не меняется до нажатия кнопки.
Полные одинаковые имена сотрудников тоже выбираются кнопками с разными ID.
Кнопки привязаны к пользователю, компании, текущим параметрам запроса и сроку
15 минут; устаревшие и чужие ID не принимаются. Подбор работает одинаково после
распознавания голоса и для текстовых вопросов.

## Затраты по чекам и проверка дат

Обычные «затраты по сотрудникам/проектам» и «сколько потратил сотрудник» означают
сумму загруженных документов, а не только согласованные расходы подотчёта.
«Принятые/согласованные расходы», «на проверке» и «отклонённые» остаются
отдельными финансовыми показателями. Общая сводка теперь показывает документы,
их количество и суммы по валютам, включая сотрудников/проекты без денежных
операций. Документы и движение денег не складываются в общий расход.

По умолчанию документы отбираются по дате загрузки — это явно написано в ответе.
Можно сказать «по дате документа» или «по дате чека», чтобы использовать дату
самого документа, а затем «по дате загрузки» для возврата. Работает для затрат
по документам, товарных позиций и документной части сводки. В сводке денежные
операции по-прежнему считаются по датам получения/согласования. Чеки без даты
при отборе по дате чека не включаются; это отмечается в ответе. Даты в базе не
исправляются и не подменяются автоматически датой загрузки.

Сотрудник в документном отчёте — тот, кто загрузил документ. Получатель выдачи
и загрузивший чек могут быть разными людьми; наличие выдачи не создаёт чеков.
Короткие запросы месяцев сохраняют выбранный вид отчёта и сотрудника. В ответах
и Excel всегда указаны границы периода и основание даты документов.
