# Панель руководителя в Telegram

Мини-приложение открывает существующий дашборд внутри Telegram. Оно использует
те же API, финансовые сервисы, базу и внутренний ID пользователя, что веб-панель
и боты. Повторно создавать сотрудника или привязывать Telegram не требуется.

Доступны обзор открытых проектов, выдача денег, проверка расходов и возвратов,
бизнес-карты, документы, проекты, сотрудники, отчёты и Excel. Нижняя навигация
ведёт в обзор, деньги, документы, отчёты и профиль; остальные разделы находятся
в меню. Кнопка Telegram «Назад» сначала закрывает открытое окно, затем возвращает
в родительский раздел. Интерфейс учитывает безопасные отступы экрана.

Вход разрешён только действующему руководителю активной компании (`manager`).
Сотрудник и владелец системы не получают через мини-приложение финансовые права
руководителя. Для владельца остаётся отдельный кабинет обычной веб-панели.

## Подключение на сервере

1. Подготовьте публичный HTTPS-домен и развёртывание по [инструкции](DEPLOYMENT.md).
   Для бота и панели нужны одна БД и один внешний origin.
2. В `.env` сервера включите мини-приложение:

   ```dotenv
   WEB_MINI_APP_ENABLED=true
   WEB_TELEGRAM_BOT_ID=1234567890
   ```

   Замените пример на числовой `result.id` метода Telegram Bot API `getMe`
   вашего бота. Это ID бота, а не ID владельца, не `@username` и не секрет.
   `WEB_BOT_USERNAME` должен относиться к этому же боту.
   Новый секрет для мини-приложения не нужен; существующий токен используется
   ботом как прежде. Не отправляйте токен в чат и не сохраняйте его в Git.

3. В конфигурации с `docker-compose.https.yml` адрес `WEB_ORIGIN` для бота и панели
   вычисляется из `WEB_DOMAIN`. При другом способе запуска явно задайте обоим
   процессам `WEB_ORIGIN=https://ВАШ_ДОМЕН` без пути и настройте reverse proxy
   согласно инструкции панели. Локальный HTTP для мини-приложения не подходит.
4. Создайте резервную копию и обновите бот вместе с панелью по инструкции
   развёртывания. Образ должен включать новую зависимость `cryptography`;
   миграция `013_telegram_mini_app.sql` применяется автоматически при старте.
   Она добавляет канал веб-сессии и таблицу использованных входов Telegram.
5. В личном чате с ботом отправьте `/start`, нажмите «Панель руководителя», затем
   «Открыть панель» в сообщении. Команда `/panel` открывает ту же кнопку.

Адрес мини-приложения: `https://ВАШ_ДОМЕН/mini`. Публичная демо-страница GitHub
Pages не является сервером этого приложения. При открытии `/mini` обычной
ссылкой без подписанных данных Telegram панель попросит открыть её через бота.

Дополнительно можно настроить в BotFather кнопку меню (`/setmenubutton`) или
Main Mini App с этим же HTTPS-адресом. Встроенный запуск использует **inline
web_app-кнопку в сообщении**: Telegram не передаёт `initData` при запуске через
`web_app` в reply-клавиатуре. Поэтому первая кнопка главного меню текстовая.

По умолчанию функция выключена. После изменения настроек перезапустите оба
процесса, чтобы панель и кнопки бота использовали одну конфигурацию.

## Авторизация

Сервер проверяет `Telegram.WebApp.initData` по официальной production-подписи
Ed25519 Telegram, с привязкой к ID бота. Алгоритм и публичный ключ:
[Validating data for third-party use](https://core.telegram.org/bots/webapps#validating-data-for-third-party-use).
Непроверенные поля `initDataUnsafe` не используются для входа.

Подписанный вход действует 5 минут и используется один раз. Повторный запрос,
включая перестановку параметров, не создаёт новую сессию. Исходные подписанные
данные в БД не сохраняются. После проверки сервер находит существующий аккаунт
Telegram, проверяет роль и компанию, затем создаёт сессию на один час.
Проверка роли выполняется и при последующих API-запросах.

Токен мини-приложения хранится только в памяти страницы и передаётся в заголовке
Authorization; localStorage, sessionStorage и сторонние cookies не нужны.
В БД хранится хеш токена. Изменения защищены CSRF-токеном и проверкой Origin.
Обычная браузерная авторизация сохраняет свой механизм HttpOnly cookies.

В «Профиле» сессии Telegram видны вместе с веб-сессиями; их можно отозвать.
Выход, истечение сессии или приостановка доступа требуют нового входа.
После перезагрузки страницы или ошибки «вход уже использован» закройте
мини-приложение и откройте заново кнопкой бота. Если клиент Telegram не передаёт
подпись, обновите его до актуальной версии.

## Проверки и приёмка

Выполнены автоматические проверки подписи, срока входа, повторного и конкурентного
использования, ролей, блокировки доступа, CSRF, общей идентичности пользователя,
Excel и запуска inline-кнопкой. В Chromium на ширине 390 px проверены обзор,
деньги, документы, отчёты, профиль, выход и кнопка «Назад». Браузерная проверка
использовала тестовый Telegram SDK и настоящий API с отдельной временной БД.

Проверка внутри настоящего Telegram остаётся этапом после развёртывания HTTPS:

- Войти руководителем через `/panel`; сверить компанию, проекты и суммы с вебом.
- Убедиться, что сотрудник и владелец системы не получают доступ руководителя.
- Создать выдачу, подтвердить её в боте, проверить учтённый расход в панели; сверить остаток
  и Excel между интерфейсами.
- Проверить навигацию, экранную клавиатуру, отступы и «Назад» на Android/iOS/Desktop.
- Проверить скачивание Excel на каждом целевом клиенте Telegram: API и браузерная
  загрузка проверены, поведение загрузок встроенного WebView требует проверки
  на устройствах.
- Проверить выход, отзыв сессии и приостановку доступа без восстановления старого
  входа после возобновления доступа.
