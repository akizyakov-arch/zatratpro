# FIINOPS: техническое задание и технологический стек

Версия 1.1 · 28.10.2026 · основание: срез `69c2842`, общие команды
`refactor/shared-application-core` и продуктовые
правила, закреплённые в текущем коде. Это консолидированное ТЗ существующей версии,
а не подтверждение установки на сервере или полного равенства интерфейсов.
Плановые изменения выделены отдельно и не считаются принятыми в эксплуатацию.

Текущий рефакторинг и границы общих форм: [APPLICATION_CORE.md](APPLICATION_CORE.md).

## 1. Цель и границы

Система должна учитывать затраты по документам в разрезе компании, проекта
и загрузившего документ сотрудника, а также выдачу денег на закупки, получение,
привязку расходов, возвраты и оплату бизнес-картами. Пользователь должен иметь
единый профиль для Telegram, MAX и разрешённых прикладных интерфейсов.

Первая рабочая модель: один руководитель на компанию, одна активная компания
на пользователя, до 10 активных сотрудников. Системный владелец не является
руководителем компании автоматически. Предметная область — управленческий
учёт, а не выполнение платежей и не бухгалтерская отчётность.

Статусы ниже: **Р** — реализовано в указанном срезе; **Ч** — реализовано частично
или в отдельных интерфейсах; **П** — будущая работа, не входящая в приёмку текущей
версии. Соответствие интерфейсов приведено в [PRODUCT.md](PRODUCT.md).

## 2. Технологический стек

Версии библиотек — допустимые диапазоны из `requirements.txt`, а не lock-файл
или гарантированно установленные версии. Среда контейнера — Python 3.12.

|---|---|---|

| Telegram | aiogram `>=3.21.0,<4` | Bot API, сообщения и кнопки |
| Telegram proxy | aiohttp-socks `>=0.10.0,<1` | HTTP/SOCKS5 доступ к Bot API |

| HTTP-клиент | httpx `>=0.27.0,<1` | MAX, OCR/LLM/STT, скачивание вложений |
| База | PostgreSQL `16-alpine` в Compose | Все предметные данные и durable-состояния |
| Драйвер БД | asyncpg `>=0.30.0,<1` | SQL, пул соединений, транзакции |
| Валидация | Pydantic `>=2.8.0,<3` | Контракты документов и HTTP-входа |

| Web API | FastAPI `>=0.115.0,<1` | Вход, панель, отчёты, операции |
| ASGI | Uvicorn `>=0.32.0,<1` | Запуск HTTP-приложения |
| Браузерный интерфейс | HTML, CSS, JavaScript без React/Vue | Адаптивная панель и Telegram Mini App |
| Изображения | Pillow `>=10.4.0,<12` | Поворот/подготовка изображений |

| Excel | openpyxl `>=3.1.0,<4` | Экспорт управленческих отчётов |
| Криптография | cryptography `>=44.0.0,<47` | Ed25519-проверка Mini App и проверки сертификатов |
| OCR | DeepSeek Vision или OCR.space | Распознавание изображения документа |

В коде нет ORM, отдельного Redis/Celery worker или отдельного сетевого сервера
ядра. Миграции — SQL-файлы с реестром `schema_migrations`. Ядро импортируется
процессами адаптеров. Отдельный API-сервис ядра — возможное развитие, не текущий стек.

Модели по умолчанию: `DEEPSEEK_VISION_MODEL=deepseek-flash`,
`DEEPSEEK_MODEL=deepseek-chat`; их имена конфигурируемые и не являются гарантией
наличия модели у внешнего поставщика. OCR.space использует текущую реализацию
с русским языком и engine 2. Доступность и тарифы провайдеров задаются ими.

| ID | Требование | Статус |

| FIN-07 | Отмена выдачи и ограничения последующих действий проверяются ядром | Р; интерфейсы различаются |
| FIN-08 | Бизнес-карта хранит название/last4; привязка своего документа фиксирует оплату | Р, Telegram/веб |
| FIN-09 | Документ не может иметь две действующие привязки к разным источникам оплаты | Р |
| FIN-10 | Новые оплаты не требуют согласования; исторические pending/rejected сохраняются | Р |
| FIN-11 | Защищённые проведённые операции нельзя произвольно отклонять или стирать | Р |
| FIN-12 | Подтверждение получения формирует надёжное уведомление руководителю | Ч, доставка Telegram |
| FIN-13 | Полный набор привязок/возвратов/бизнес-карт в MAX | П; денежные сервисы общие, интерфейс неполный |

Формулы и трактовки:

- Затраты = сумма сохранённых затратных документов выбранного разреза/периода.
- Остаток подотчёта = подтверждённое получение − учтённые расходы из этих денег
  − подтверждённые возвраты. Неподтверждённая выдача в остаток не входит.
- «У сотрудников» и «Компания должна» выделяются после сведения по каждому
  сотруднику; положительные остатки одних людей не гасят долг перед другими.
- Оплаты картой отдельно от подотчёта. Не суммировать повторно документ с его оплатой.
- Документ без источника оплаты — затрата с неуказанным способом расчёта.
- Документы в разных валютах не суммируются и не конвертируются. Денежный контур
  выдач/карт пока RUB. Дубль помечен, но автоматически не исключается из затрат.

Фактические тайм-ауты: обработка PDF OCR до 600 с; общий приём/распознавание

Нагрузочные нормативы, RPO/RTO, срок хранения, целевой uptime и бюджет внешних API
не согласованы и не подтверждены нагрузочными испытаниями. Их следует определить
отдельно перед промышленной эксплуатацией; числовых гарантий данное ТЗ не задаёт.

## 5. Контейнеры и конфигурация

Тестовый профиль двух ботов — три процесса/контейнера: PostgreSQL, Telegram,
MAX. Включение панели добавляет `zatratpro-web`, публичный HTTPS — `caddy`.
Ядро — общий Python-код внутри адаптеров, а не четвёртый «контейнер ядра».
Общая БД должна быть одной для подключённых интерфейсов.

Конфигурационные группы: `POSTGRES_*`, `TELEGRAM_BOT_TOKEN`,
`BOT_OWNER_TELEGRAM_ID`, `MAX_BOT_TOKEN`, `OCR_SPACE_API_KEY`, `DEEPSEEK_*`,
`ASSEMBLYAI_API_KEY`, `WEB_*`; подробности — [OPERATIONS.md](OPERATIONS.md).
Пустая база инициализируется `db/init/001_init.sql`, затем применяются миграции
001–024. Миграция 022 меняет поле владельца черновика: старые процессы должны
быть остановлены перед запуском новых.

## 7. Открытые работы и исключения

| Направление | Текущее состояние | Что потребуется для отдельной приёмки |
|---|---|---|
| Фоновое распознавание | П: MAX polling обрабатывает OCR последовательно | Очередь, worker, повторы, отмена, восстановление, лимиты параллелизма |
| Production MAX | П: доступен тестовый polling | HTTPS Webhook, проверка секрета, повторная доставка и эксплуатационные проверки |
| Финансовый интерфейс MAX | Ч: выдачи/получение/отчёт есть | Привязки чеков, возвраты, карты и уведомления в том же ядре |
| Архив исходников | П | Хранилище, доступ, срок хранения, резервирование и удаление |
| Выписки банка | П | Импорт, сопоставление с документом/проектом и защита от двойного учёта |
| Редактор распознанного документа | Вне текущего объёма | Отдельное согласование; не добавлять скрыто при развитии OCR |
| Обновление зависимостей/CI | Диапазоны зависимостей, локальные тесты | Зафиксированные сборки, политика обновлений и автоматический pipeline |

Эти работы не дают оснований менять действующие финансовые правила без
отдельной постановки. Очерёдность и сроки не являются частью утверждённого релиза.
