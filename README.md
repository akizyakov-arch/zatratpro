# ZATRATPRO

MVP Telegram-бота для распознавания чеков, актов и накладных.

## Что умеет каркас

- запускает Telegram-бота на `aiogram`
- обрабатывает `/start` и `/help`
- принимает фото
- скачивает файл во временную папку `tmp/`
- отправляет фото в OCR.Space
- передает OCR-текст в DeepSeek
- валидирует JSON по контракту документа

## Требования

- WSL2 Ubuntu
- Python 3.11+
- Telegram Bot Token
- OCR.Space API key
- DeepSeek API key

## Быстрый старт

```bash
cd ~/DEVV/ZATRATPRO
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
python -m app.main
```

## Структура

## Надёжность и состояние

При запуске после подключения к PostgreSQL автоматически применяются версионированные
миграции из `db/migrations/` в транзакции с блокировкой. Они добавляют новые поля и
таблицы, не удаляя существующие документы. При первом создании БД по-прежнему нужна
исходная схема `db/init/001_init.sql` (Docker Compose применяет её автоматически).
Пользователю БД нужны права на изменение схемы. Перед обновлением сделайте резервную
копию БД. Docker-образ включает файлы миграций.

Черновики документов и незавершённые действия хранятся в PostgreSQL с TTL 15 минут.
Они переживают перезапуск; истёкшие записи недоступны и очищаются при запуске и новых
операциях. Если процесс прервётся во время самого OCR/LLM-запроса, этот запрос не
возобновляется автоматически. Повторный callback одной загрузки не создаёт вторую
запись, при этом отдельно загруженные одинаковые документы можно осознанно сохранить.
Кнопки привязаны к конкретной загрузке; старые кнопки не изменяют новый черновик.

Единственный действующий владелец задаётся `BOT_OWNER_TELEGRAM_ID`; сохранённая роль
прежнего владельца не даёт доступа после смены ID и перезапуска. Обрабатываемые
фотографии считаются временными и удаляются после OCR, включая ошибки. Архив
оригиналов эта версия не ведёт. Excel-экспорт сохраняет пользовательские строки
как текст, а диагностические логи скрывают известные секреты и токены Telegram.

## Тесты

Без внешних API и без PostgreSQL:

```bash
python -m unittest discover -s tests -p 'test_unit.py' -v
```

Полный набор (пользователь PostgreSQL должен иметь право `CREATEDB`):

```bash
# POSTGRES_HOST, POSTGRES_PORT, POSTGRES_USER, POSTGRES_PASSWORD задайте в окружении.
RUN_DATABASE_TESTS=1 python -m unittest discover -s tests -v
```

Тесты создают отдельную базу со случайным именем `test_zatratpro_*` для каждого
сценария и удаляют её после проверки. `POSTGRES_DB` не используется как тестовая
база. Тесты не отправляют сообщения в Telegram и не вызывают OCR.Space/DeepSeek.
Проверяются гонки приглашений/лимита сотрудников, идемпотентность сохранения,
изоляция компаний, смена владельца, восстановление состояния, маршрутизация
callback, очистка файлов и типы ячеек XLSX. При отсутствии `RUN_DATABASE_TESTS=1`
интеграционные проверки явно пропускаются.
